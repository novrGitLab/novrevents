# Security

## Controls in place

| Concern                  | Control                                                                                                                                                                                                                                                                                            | Where                                                                   |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Passwords                | scrypt (N=2¹⁷ in production, parameters stored per hash, transparent rehash), 10+ chars, common-password and "same as email/username" rejection                                                                                                                                                    | `src/lib/crypto.ts`, `auth.service.ts`                                  |
| Account enumeration      | Identical login errors, constant-time dummy hash for unknown emails, forgot-password always succeeds                                                                                                                                                                                               | `auth.service.ts`                                                       |
| Sessions                 | 256-bit random token, only SHA-256 stored, HTTP-only, `Secure` in production, `SameSite=Lax`, revocable; password reset revokes all, password change revokes others, suspension revokes all                                                                                                        | `plugins/auth.ts`                                                       |
| CSRF                     | Origin allow-list + per-session HMAC token header on every state-changing request                                                                                                                                                                                                                  | `plugins/auth.ts`                                                       |
| Authorization            | Server-side guards per resource; unrelated callers get 404; check-in staff cannot read form responses; admin routes behind a plugin-level hook                                                                                                                                                     | `event-access.ts`, `form-access.ts`, `org-access.ts`, `admin.routes.ts` |
| Input validation         | Zod on params, query and body for every route; form answers re-validated by the engine on the server                                                                                                                                                                                               | route files, `forms/engine`                                             |
| Output filtering         | Response schemas strip undeclared fields; password hashes, tokens and storage keys never leave the API                                                                                                                                                                                             | route files                                                             |
| SQL injection            | Prisma queries and tagged `$queryRaw` templates only                                                                                                                                                                                                                                               | —                                                                       |
| Uploads                  | Size limits; type detected from content (not name); images re-encoded to WebP with metadata stripped; documents restricted to an allow-list with content/extension match; random server-side keys; private uploads only via authorised routes, always `Content-Disposition: attachment`, `nosniff` | `lib/uploads.ts`                                                        |
| Rate limiting            | Global 300/min/IP, tighter on auth, password reset, public forms, reports, beacons and scanning                                                                                                                                                                                                    | `plugins/rate-limit.ts`                                                 |
| Duplicate submissions    | Idempotency key + configurable duplicate rule, both enforced by unique indexes                                                                                                                                                                                                                     | `public-form.service.ts`                                                |
| Limits under concurrency | Row locks + CHECK constraints                                                                                                                                                                                                                                                                      | see `DATABASE.md`                                                       |
| Ticket forgery           | HMAC-signed QR payloads; validity decided server-side; one check-in per ticket by unique constraint; every scan logged                                                                                                                                                                             | `ticket-credential.ts`, `attendance.service.ts`                         |
| Guest links              | Registration links are signed with an access version that can be bumped to invalidate them                                                                                                                                                                                                         | `ticket-credential.ts`                                                  |
| Email injection          | Organiser text is HTML-escaped in templates; CSV exports neutralise spreadsheet formulas                                                                                                                                                                                                           | `lib/email/render.ts`, `lib/csv.ts`                                     |
| Abuse                    | Verified email required to publish and send; daily publish cap; invitation cap; announcements only to registrants; one report per reporter; auto-flag at a report threshold; moderators can remove events and suspend accounts/organisations                                                       | `event.service.ts`, `communication.service.ts`, `discovery.service.ts`  |
| Privacy                  | Registered-event sharing off by default and followers-only; private profiles 404; public profile fields opt-in; analytics visitor keys are daily-rotating salted hashes; unsubscribe for all optional mail; configurable response retention                                                        | —                                                                       |
| Audit                    | Sensitive actions (auth changes, publishing, cancellation, exports, deletions, team/role changes, moderation, settings) written to `audit_logs` with actor, IP and request id                                                                                                                      | `lib/audit.ts`                                                          |
| Headers                  | API: `default-src 'none'` CSP, HSTS in production, `nosniff`. Web: `X-Frame-Options: DENY`, `nosniff`, referrer policy, camera limited to self                                                                                                                                                     | `app.ts`, `next.config.ts`                                              |
| Logs                     | Cookies, auth and CSRF headers redacted                                                                                                                                                                                                                                                            | `app.ts`                                                                |

## Deployment requirements

- `NODE_ENV=production`, `COOKIE_SECURE=true` (enforced at startup), a unique `SESSION_SECRET` of 32+ random characters.
- Run behind TLS. Set `TRUST_PROXY=true` only when a reverse proxy you control sets `X-Forwarded-For`.
  When the API is reached through Vercel rewrites, rate limits are keyed on the address the proxy chain
  reports; review this if you need strict per-client limits.
- `BREVO_WEBHOOK_TOKEN` must be long and random; keep `API_DOCS_ENABLED=false` publicly.
- PostgreSQL must not be exposed to the internet (Railway private networking; no public TCP proxy).
- Uploads live on one Railway volume, so the API runs as a single replica (see `DEPLOYMENT.md`).

## Known limitations

- Rate-limit counters are in memory per process (correct for one API instance). Multiple instances need a shared store.
- No multi-factor authentication yet.
- Uploaded documents are type-checked but not virus-scanned. Organisers download them as attachments; add a
  scanner (e.g. ClamAV) before accepting files from untrusted audiences at scale.
- The privacy policy and terms pages describe the implementation in plain language and need legal review.
