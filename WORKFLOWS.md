# Event platform workflow map

Research date 27 November 2026. The signed-in Eventbrite review used a private draft named “NovrEvents private workflow review.” A draft can be reached from the account’s Events list. Availability of tools depends on account, region, plan and publication state.

| Workflow | Evidence from Eventbrite | NovrEvents contract and intended behavior |
| --- | --- | --- |
| Discovery | Public search, location, date, themes, organizer pages and saved events | Preserve public slugs and filters, and present date, place, admission and organizer together. [Lagos directory](https://www.eventbrite.com/d/nigeria--lagos/events/) |
| Authentication | The signed-out registration and sign-in entry share a required email field. Submitting an empty address displayed a validation error. Google, Apple and Facebook were available. The account step links the terms and privacy policy and identifies hCaptcha. Help documents email challenges and optional MFA. The existing organizer session was reused. | Keep password sign-in, verified email, unique handle, session and CSRF controls. Google identity should bind by issuer and subject. Verified Gmail and matching Google Workspace addresses can link to an existing verified account. Other existing addresses use authenticated linking. [Account access](https://www.eventbrite.com/help/en-us/articles/277134/) |
| Assisted creation | Required title, dates/times, venue mode, price or free switch, total quantity. Optional tone, audience, and 2,000-character context. Summary, description, category and tags suggested from title. | An optional NhaAI draft can suggest copy and tags from organizer-provided public facts. Organizer reviews changes. Price, capacity, location, visibility and publication remain explicit. |
| Page builder | Manual title and summary (140 characters), photos/video, long overview, single/recurring schedule, time zone, language and display controls | Reuse the event, agenda, category and speaker models. Preserve one IANA zone per schedule. Validate end after start. Design recurring occurrences separately from the parent event and each ticket inventory. |
| Location | Venue, online or to be announced. Manual venue requires name, address 1, city and country. Address 2 and region are optional. Reserved seating appears for venues. | Store venue and online access separately. Never include restricted join URLs in discovery or flyer data. Keep online-only, in-person and hybrid modes supported. |
| Event information | Age, door time, parking, FAQs, lineup and agenda are optional sections. Parking disappears for a TBA venue. | Show only applicable sections in the public page. Keep speaker/order relationships with event-owned records. |
| Tickets | Paid, free and donation. Free disables price. Name (50), quantity, sales dates/times, optional description (2,500), visibility schedule, min/max, channel, eTicket, will call, optional check-in window and sell-out alerts. Sections share capacity. | Reservation, payment, attendee and admission credentials need separate records. Stock and per-order limits belong in a transaction. Never use a browser-calculated amount as payment authority. |
| Order form | The draft defaulted to collecting name and email from the buyer. Each-attendee collection is optional. The organizer can split questions before and after payment, allow later contact edits, set a completion deadline and add checkout instructions. The screen derives question count and estimated completion time. The help center describes conditional follow-ups and per-ticket rules. | Reuse the existing versioned conditional form engine and server-side submission evaluation. Store order-level and attendee-level answers separately when checkout is introduced. [Custom questions](https://www.eventbrite.com/help/en-us/articles/228823/how-to-create-custom-questions-for-attendees/) |
| Organizer operations | Order confirmation, waitlist, orders, guest lists, add attendees, emails, check-in, reports and analytics. Some controls disabled in draft. | Build on existing registrations, review queues, attendance, communications, tasks, certificates and analytics. Enforce event ownership and team permissions at every mutation. |
| Organization | Events, orders, marketing, reporting, finance, settings and apps were visible in signed-in navigation. | Keep customer tickets and organizer tools in the same identity; platform administration uses a separate guarded entry. Financial workflows need a merchant contract, currency and payout policy. |
| Promotion | Eventbrite documents shareable QR flyers. | Offer an original poster studio with five treatments, editable copy, a stable public event destination and print/PDF. QR must identify the listing, never an attendee or private admission credential. [Product updates](https://www.eventbrite.com/product-updates) |
| Planner requests | Product-specific extension | Capture contact, expected attendance, date/location and scope. Admins triage new requests. Private contact details must never appear in discovery, SEO, or model prompts. |

### Derived values and trust boundaries
The server owns immutable IDs, actor identity, permission scope, issued ticket identifiers, accepted quantities and aggregate counts. The client may preview dates, layouts and total estimates. The API revalidates domain invariants. Draft links, access keys, ticket codes, attendee data and checkout sessions must stay out of canonical URLs and sitemaps.

### Evidence limits
The live review reached manual draft creation, ticket setup, advanced ticket controls and organizer menus. The live order form and disabled-by-default waitlist were also inspected. Waitlists can open at capacity or when a visible ticket type sells out. Maximum list size, optional phone collection and a timed invitation are documented. [Waitlist controls](https://www.eventbrite.com/help/es-mx/articles/811539/como-configurar-una-lista-de-espera-de-un-evento/) Paid checkout, provider settlement, refunds, reserved seating, MFA enrollment and post-publication tools still require independent end-to-end verification. Full new-account registration was not completed in the existing signed-in account.

### NovrEvents delivery and remaining differences

| Area | Available in NovrEvents | Eventbrite workflows still outside this release |
| --- | --- | --- |
| Guest preparation | Organizers set minimum age, accessibility notes, venue parking, a doors-open offset and ordered questions and answers. Public details derive doors-open time from the event’s start and time zone. Online-only events omit venue details. | Reserved seating and seat selection. |
| Ticket orders | One registration per attendee, free tickets, reviewed applications, NGN hosted checkout, final server-side verification, protected ticket QR, PDF and duplicate check-in detection. Test payments have separate organizer subaccounts and never issue admission. | Multi-attendee baskets, buyer versus guest answers, post-purchase questionnaires, donation tiers and promotional codes. [Eventbrite discounts](https://www.eventbrite.com/help/en-us/articles/448974/create-a-discount-on-tickets/) |
| Capacity and scheduling | Event and ticket-type limits, transactional reservations, hold expiry, agendas, one time zone per event and event duplication. | Waitlist invitation expiry and recurring occurrences with separate inventory. [Time slots](https://www.eventbrite.com/help/en-us/articles/101829/) |
| Settlement | Verified NGN subaccounts and manual reconciliation for exceptional charges. | Self-service refunds and a settlement dashboard. [Eventbrite payment processing](https://www.eventbrite.com/help/en-us/articles/426093/getting-started-with-eventbrite-payment-processing/) |
| Promotion | Five customizable flyer designs, QR links to registration, PDF export, a public flyer link and planner requests. | Attribution reporting across campaigns and marketing integrations. |

The private draft provided organizer-side evidence. It did not establish the behavior of published settlement, refunds or a newly registered Eventbrite user. The checkout implementation is tested locally with provider fixtures. Merchant acceptance requires a separate Paystack test transaction.

### Account entry and form workspace, 28 November

The signed-out Eventbrite entry showed one email field, a Continue action, social sign-in and a human-check notice. Its account help describes emailed codes. NovrEvents uses a self-hosted human check and a six-digit code. First-time email entrants set a password. Returning verified members can use either a code or their password. Google can enroll a new account or sign in a returning member through the same action. Gmail sending requires its own administrator grant. [Eventbrite account help](https://support.eventbrite.com/hc/en-us/articles/37233967299858-Log-in-to-Eventbrite-troubleshooting-guide)

Organizers can filter form lists by publication status and purpose. The builder groups the outline and question settings under Edit questions. Preview form presents the respondent view. Both use the same form definition and conditional rules.

### Coverage of the production brief

| Area | Implementation and acceptance boundary |
| --- | --- |
| Public experience | Landing, discovery, event details, organizer profiles, event planning, ticket help, guides, legal pages, shared header/footer, original photography, cookie choices, sitemap and robots. Published events supply listing data. |
| Portal | Attending and Organizing have distinct overview views. Forms support publication and purpose filters, a question editor and guest preview. Event setup links directly to basics, schedule, location, registration and branding. Administration is role-guarded. |
| Promotion | Flyer studio provides five editable layouts, print/PDF, a public flyer route and a registration QR. Planner requests appear in administration. |
| Infrastructure and payments | Same-origin web requests proxy to the API. GitHub Actions verifies changes before deploying the release to Contabo. Paystack uses NGN in test mode. Live transactions and payouts require a deliberate mode change and merchant acceptance. |
| Identity and messaging | Password, code and Google entry share the Events account. Gmail sending requires an independent send-only grant from the designated mailbox. Delivery becomes active after Google accepts the confirmation message. |
| Assisted creation | Verified organizers can request a description draft when a dedicated NhaAI key, model and service endpoint are configured. Applying the draft and publishing the event are organizer actions. |
| Quality and security | Desktop and mobile browser checks cover signup, discovery, form creation, attendee check-in, planner requests and flyer sharing. The build also checks the generated API contract, production dependencies, authentication, ownership and ticket boundaries. |
